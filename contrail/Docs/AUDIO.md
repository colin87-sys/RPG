# AUDIO — CONTRAIL procedural audio plan (GAME_FORGE W8)

Status: implemented, agent-verified numerically, pending owner review (not audible to the agent)

All sound is Web Audio synthesis in `src/gen/audio/`: oscillators, noise buffers generated by code with `Rng`, biquad filters, envelopes, waveshapers and a convolver with a code-generated impulse. There are no samples, no files and no `Math.random()`.

| File | Role |
|---|---|
| `engine.ts` | `AudioEngine` (public API), `VoiceManager` (voice limits, stealing, auto-duck) |
| `mixer.ts` | buses, reverb, master chain, `duck()` |
| `sfx.ts` | 20 recipes `(ctx, out, t0, params) => SfxVoice`, `SFX_INFO`, `lockPitch()` |
| `music.ts` | `MusicPlayer` (lookahead scheduler), `renderLoopOffline()`, stage flavours |
| `offline.ts` | `renderForCheck()`, `checkMixer()`, analysis, STFT spectrograms |
| `bind.ts` | optional `bindGameAudio(engine, bus)` event wiring + `musicIntensity()` |
| `dsp.ts`, `levels.ts` | noise banks, curves, IR, envelope helpers, master constants |

Evidence: `look/candidates/audio_A.png` (board `lab/index.html?board=audio`), numbers in `look/candidates/audio_A.json`, and `window.__audioResults` on the board page.

## Music
- **Key A minor (Aeolian), 140 BPM, 4/4, 16-bar loop = 27.43 s.** Four chords x 2 bars, played twice. The second half uses arp pattern B and, at intensity >= 0.75, the bass octave pattern. Fills come in bars 8 and 16 at intensity >= 0.7, and a crash at bars 1 and 9 at intensity >= 0.75.
- Stage flavour: tempo and key are fixed; timbre, progression and groove change.

| Stage | Progression | Timbre / groove |
|---|---|---|
| cloudgate | i-VI-III-VII (Am F C G) | bright saw bass (LP 1 kHz), square 1/16 arp up-down, pad detune 11 c, kick 1 / 3 / &3 |
| violetTide | i-VI-iv-V (Am F Dm E) | round saw bass with octave bounce, triangle syncopated arp + more delay, pad detune 18 c (darker), kick 1 / &2 / 3 |
| wreckfield | i-bII-VII-V (Am Bb G E) | square bass, driven, with fifth/octave; low saw arp (-1 oct); pad detune 25 c, LP 950 Hz; galloping kick 1 / a1 / 3 / a3 |

- Layers: **pad** = 8 continuous detuned saws (4 voices, legato retune at chord changes plus a filter swell) through LP, spread L/R. **bass pulse** = 1/8 notes, saw/square + sine through an enveloped LP and a shared soft clip. **percussion** = kick (sine 150->46 Hz drop), snare (BP noise + triangle), hats (HP noise, 16ths at intensity >= 0.85, open hat on odd bars), crash. **arpeggio** = 1/16 chord tones with a dotted-8th feedback delay.
- Humanisation: per-bar `Rng(hashString(stage:bar, seed))` gives offsets of about +-4 ms on hats and +-2 to 3 ms on snare/arp/bass (downbeats on grid), plus velocity 0.86-1.0.
- **Intensity -> layer gain** (`layerGains`): pad `1 - 0.25*ss(0.5,1,x)`, bass `ss(0.05,0.35,x)`, percussion `ss(0.3,0.6,x)` (snare from 0.42), arp `ss(0.5,0.8,x)`. Intensity also opens the bass/arp/pad filters. Changes glide with a 0.6 s time constant.
- **Game intensity** (`musicIntensity`): `0.3 + 0.35*min(1, chain/8) + 0.3*danger + 0.3*(boss)`, clamped to 0..1. `danger = max(1 - shield/100, hit heat)`, where hit heat is +0.35 per hit and decays over 3 s. Suggested menus/hangar value: 0.15.
- Scheduler: `setTimeout` every 25 ms, 0.2 s lookahead on `ctx.currentTime`. If the tab was throttled it skips ahead on the grid instead of bursting. `setStage` while playing crossfades over half a bar at the next bar line.

## Mix
| Bus | Level (linear) | Notes |
|---|---|---|
| sfx | 0.8 | reverb send 0.12 |
| ui | 0.6 | dry |
| music | 0.36 | -> duck gain; pad/arp send to reverb |
| reverb return | 0.5 | convolver, code-generated stereo IR 1.6 s, RT60 1.3 s, darkening tail |
| master | 1.0 | `setMasterVolume(v)` after the ceiling, so it can never exceed it |

Master chain: highpass 18 Hz (DC blocker) -> DynamicsCompressor (-6 dB, knee 3, 16:1, 1.5 ms / 120 ms) -> waveshaper ceiling (identity below 0.75, tanh to 0.89, so the hard max is about -1.1 dBFS) -> volume -> destination.

**Ducking:** `duck(db, s)` gives a 30 ms attack, a hold and a 350 ms release. Overlapping ducks keep the deepest depth and the latest end. Auto-duck: warning -8 dB / 1.0 s, explosionBig -6 dB / 0.7 s, parry -5 dB / 0.35 s. Measured: -8.0 dB for an 8 dB request (`checkMixer`).

## Check method (`renderForCheck`, board `audio`)
- Each SFX is rendered in its own `OfflineAudioContext` (48 kHz stereo) through `VoiceManager` + `Mixer`, the same code path as the game. cannon = 7 shots at 14/s; lockTone = locks 1-4. Music = one loop + 1 s at intensity 0.25 / 0.6 / 1.0 (cloudgate), plus 0.6 for violetTide and wreckfield.
- **0.3 s silent pre-roll, cropped before analysis.** Chromium's DynamicsCompressor ramps up for about 100 ms after a context starts: a steady tone read -24.6 dB in the first 50 ms against -16.6 dB settled. In the game the mixer exists long before any cue, so the pre-roll measures the steady-state chain. Without it every loop-seam check failed by 6-9 dB.
- Metrics: peak (dBFS), RMS (SFX: 10 ms frames within 20 dB of the loudest frame; music: over one loop), DC (worst channel mean), clipping (|x| >= 1). Seam: RMS of the first 50 ms vs 50 ms after the loop point (<= 3 dB) and |x[L]-x[L-1]| <= 0.1.
- Targets: peak <= -1 dBFS, no clipping, |DC| < 0.01, SFX RMS -30..-10, music RMS -24..-12 at intensity 0.6.
- Spectrogram: STFT 1024 Hann, hop 256, log frequency 30 Hz-16 kHz, colours spaceDeep -> hudLine -> hudText -> burstYellow -> burstWhite (-100..-12 dB for SFX, -100..0 dB for the dense mean-pooled music strips).
- Offline music scheduling is bar-by-bar via `ctx.suspend()`, which cut render time by about 3.5x. The whole board takes about 24 s.

## Open issues
- Nothing has been listened to. Balance and timbre are pending owner review. The first listening candidates are the loudness of explosionBig and wingtrail against the music, and whether the cannon at 14/s is fatiguing.
- The music RMS at intensity 1.0 equals 0.6 (-17.4). The extra layers are absorbed by the pad ducking and the master compressor, so intensity changes are felt as density and brightness rather than level. Raise `LAYER_LEVELS` if the owner wants a louder climax.
- `laserFire` has no cue (suggested: reuse `bossBeamCharge` release or add a beam recipe).
- Browsers need a user gesture: `AudioEngine` auto-installs one-shot pointer/key listeners that call `unlock()`. `play()` is ignored while the context is suspended; the music scheduler waits.
